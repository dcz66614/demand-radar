## Actual workaround and impact
No reliable workaround is documented in the record. What reporters actually do: AgentLab absorbs failures with long pauses by default — 60 seconds per missed attempt, worst case about 16 minutes per step (AgentLab #182) — and re-run evaluations accepting lower reproduced scores (WebArena 25 vs 31.4 reported, #249). For the silent tokenizer substitution (#340) and the missing streaming-completed event (#41708) there is no workaround in the record at all: both failures are silent, so the user cannot work around what they cannot see. The HN poster (#50382039) asks how to verify AI responses quickly and no verified answer is recorded.

Measured in the evidence: count_tokens() silently substitutes the GPT-4 tokenizer for every non-bare-OpenAI model name, with measured error 0% on code, +11.7% on English prose, +18.5% on Japanese and +108.3% on Chinese, and the wrong count feeds prompt trimming (AgentLab #340). Benchmark results are not reproducible: GenericAgent-GPT-4o reproduces WebArena at 25 against 31.4 reported (#249). A WorkArena L3 evaluation never stops running even after hours (#323). Responses API streaming never emits a completed event for function_call, so the agent never learns the call finished (LangChain #41708, filed three times by one author and counted once). CAPTCHA interrupts Google search in the demo (#187).

## Sample input
Two recorded reproducers, both from the evidence. (1) AgentLab #340: count_tokens(text, model=<a litellm-style non-OpenAI model name>) on a Chinese passage. (2) LangChain #41708: the Responses API event sequence response.output_item.added, then response.function_call_arguments.delta events, then response.output_item.done, for a function_call.

## Expected output
(1) The token count is within 2% of the true tokenizer for the named model; the GPT-4 tokenizer value is rejected as wrong. (2) The streaming handler emits exactly one completed generation chunk when response.output_item.done arrives — and emits none if it never arrives.

## Acceptance tests
1. count_tokens with a litellm-style model name on the #340 Chinese passage returns a count within 2% of that model's real tokenizer; the GPT-4 tokenizer value is rejected as wrong.
2. Feeding the #41708 event sequence (added + deltas + done) emits exactly one completed chunk; without the done event, no completed chunk is emitted.
3. A 429/timeout fault injected into a call is reported as a failure with the attempt count and elapsed wait, never silently retried past the stated budget (AgentLab #182: 60s per attempt, ~16 min worst case per step).
4. A response whose content fails a schema/validation check is flagged as a wrong result, not passed through as a success.
5. The HN case (#50382039): an OpenRouter response that is false, or errors after a long wait, is classified (false / timeout / error) with the elapsed time, not returned as a normal result.
