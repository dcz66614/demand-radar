## User task

## Actual workaround and impact
No working workaround is recorded for the wrong-value cases. Reporters file the bug; adjacent reports show people pinning versions instead (NeuroKit #1236: the setuptools<82 upper bound blocks picking up setuptools security fixes) or avoiding the broken function. Nothing in the record shows a user getting correct values out of the failing functions by another route.

Wrong values, all measured in the evidence: fractal_dfa returns different scaling exponents for the same signal depending only on the amplitude units it is expressed in, and raises for sufficiently small-amplitude input (#1208); emg_process() accepts the EMG sampling rate but its amplitude filter silently assumes 1 kHz, so at 4 kHz the filter frequencies shift fourfold and can change whether muscle activity is detected (#1212); RSA_PorgesBohrer comes out negative because it is computed on heart rate instead of heart period (#1230); rsp_intervalrelated phase durations come out too small on epoched data (#1196). Crashes: signal_recompose() is broken on the homepage example (#1200); rsp_process() raises IndexError on an 8-second simulated recording (#1242); signal_power.py calls np.trapz, removed in numpy 2.0, raising AttributeError (#1183); hrv(show=True) raises KeyError on ppg_peaks output (#1238).

## Sample input
Two recorded reproducers. (1) NeuroKit #1212: PhysioNet's public healthy EMG example recorded at 4 kHz, passed to emg_process(). (2) NeuroKit #1230: an ECG recording passed to hrv_rsa() with RSA_PorgesBohrer requested.

## Expected output
(1) The EMG amplitude filter frequencies are computed from the actual 4 kHz sampling rate, not an assumed 1 kHz. (2) RSA_PorgesBohrer is positive, in ln(ms^2), computed on heart period — never on heart rate.

## Acceptance tests
1. emg_process() on the 4 kHz PhysioNet EMG example from #1212 uses 4 kHz filter frequencies; muscle-activity detection matches the 1 kHz reference within the stated tolerance.
2. hrv_rsa() on the #1230 ECG input returns RSA_PorgesBohrer >= 0 in ln(ms^2); a build that feeds heart rate instead of heart period fails this check.
3. fractal_dfa() on the same signal expressed in two amplitude units returns the same scaling exponent (within 1e-6); small-amplitude input does not raise (#1208).
4. rsp_process() on the 8-second simulated recording from #1242 completes without IndexError and returns a result covering about two respiratory cycles.
5. signal_power() on numpy 2.x completes without AttributeError (no np.trapz call, #1183).
