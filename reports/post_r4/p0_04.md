## 1. Provenance rules (same as R4-04, kept)

- `RELEASE_SHA256.txt` is written OUTSIDE the zip (next to it in
  `~/projects/` and uploaded to Drive alongside it) with the final
  SHA-256, the byte size, and the generation time. The zip never
  contains its own hash — no self-reference.
- The POST-R4 final report's header states the QA status for THIS
  zip only: "the independent QA verdict for POST-R4 is pending (see
  §13) — the REWORK4 verdict (ACCEPTED_RESEARCH_PROTOTYPE_ONLY)
  applied to the REWORK4 zip only, not to this one." §13 is filled
  by the independent QA agent AFTER it verifies the final zip bytes
  (see `p0_05.md`).
- The independent QA for POST-R4 runs against the FINAL zip bytes
  (see `p0_05.md` §3) — not against an intermediate build.

## 2. Packaging (new in POST-R4: deterministic build)

- `reports/post_r4/build_zip.py` builds the zip: single top-level
  directory `demand-radar-post-r4/`, sorted entries, FIXED zip
  timestamps (1980-01-01), exclusions `.venv/`, `.venv-real/`,
  `__pycache__/`, `.pytest_cache/`, `.ruff_cache/`, `*.egg-info`,
  and the ~20 MB `reports/rework1/review_r02_raw_github.json`
  (documented in-package by
  `reports/rework1/EVIDENCE_ARCHIVE_NOTE.md`).
- `reports/post_r4/gen_manifest.py` generates
  `reports/post_r4/MANIFEST.sha256` (paths relative to the project
  root, manifest itself excluded) BEFORE the zip is built.
- **Two bugs in my own first draft of these scripts, both caught by
  the clean room (not by the work-tree checks):** (1) the egg-info
  exclusion tested `".egg-info" in rel.parts`, but the real
  directory is named `demand_radar.egg-info` — so 5 egg-info files
  got into the pass-1 zip and MANIFEST, and the clean-room
  `pip install -e .` regenerated `SOURCES.txt` with different
  content, failing the MANIFEST check; (2) `gen_manifest.py` had
  its imports in the wrong order (I001) — the work-tree `ruff check`
  had last run BEFORE the scripts were created, so it never saw
  them. Both fixed (exclusion now matches any part ENDING with
  `.egg-info`; imports reordered; `ruff format` applied), the
  egg-info directory removed from the work tree, MANIFEST
  regenerated, zip rebuilt. The lesson is recorded here rather than
  hidden: the clean room exists precisely to catch what the build
  tree's own checks miss.
- Because timestamps are fixed, a rebuild from the same tree is
  byte-identical — the pass-1 → final diff can be verified by zip
  SHA, not only by per-file content comparison (the R3/R4 method,
  kept as a fallback).
