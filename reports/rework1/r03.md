## Author-hash limitation (honest note)

R02 author hashes have NOT landed yet: at score time, 0 of 218 source_items had
author_hash and 0 had review_verdict. So today's groups are repo/context-level
only. The code already derives groups from (author_hash, repo) when hashes
exist, so re-running `python -m demand_radar score` after R02 lands will pick
them up with no code change. Known limitation: same author filing the same
demand in two repos counts twice under (author, repo); R02's author-hash review
is expected to flag those, and the count is therefore an upper bound on
person-level independence until then. Cross-org corroboration is judged
separately by distinct org keys and is unaffected by this.

## Addendum — parent correction after R02 hashes landed (2026-11-05 ~21:15 UTC)

First R03 implementation counted distinct (author_hash, repo) pairs. Once
author hashes landed that re-inflated E: AI 19 raw -> 14 pairs -> total 80
again, and a pandas-only theme (7 authors, 1 repo) reached 80. That is the
same inflation the audit flagged, at finer granularity. Corrected to the

R05 gate additionally requires >= 2 distinct authors. Scores after
correction: max 70, 5 pains >= 70 — AI 70 (3 orgs, 14 authors), FIN 65
(2 orgs, 5 authors), matching the audit's P0-02 arithmetic exactly.

Also fixed: evidence counting now excludes REJECTED sources (4 verified-only
filters in score.py + ranking.csv URLs). Pain 0b7adcf63ec0f2075fab had 2
rejected OpenBB links, but OpenBB still has 1 VERIFIED link, so its org
count stays 3 and its score stays 70. New test
test_rejected_sources_do_not_count_as_evidence added. Full suite: 77 passed.
