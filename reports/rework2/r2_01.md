## Fixes (all in the two target files)
1. **RSA** (`mvps/r1_b/signalcheck.py::check_rsa`): removed the false
   "RSA >= 0" premise (RSA is ln(variance); negative when variance < 1
   ms^2). Old code divided by the SIGNED expected value, so for
   expected < 0 the relative error was negative and any reported value
   passed. New rule: `delta = abs(reported - expected)`,
   `scale = max(abs(expected), 1e-8)`, pass iff
   `delta <= max(abs_tol, rel_tol * scale)` with abs_tol = 0.05 ln(ms^2)
   (~5% variance change, e^0.05 = 1.051 — the smallest difference the
   #1230 reproducer can meaningfully distinguish) and rel_tol = 0.02
   (keeps the bound sane for large |expected|; near zero the absolute
   term rules). Non-finite reported/input, short (<8) and empty series
   return a failed CheckResult with a reason instead of raising or
   passing. `rsa_from_period` docstring corrected; value unchanged.
2. **RSP phase** (`check_rsp_phase`): validates BEFORE zip — length
   mismatch, fs <= 0 / non-finite, non-increasing or non-finite
   intervals, non-finite/negative reported durations, unknown unit all
   return failed CheckResults. `[1, 1, 999]` for 2 intervals now fails.
3. **JSON schema** (`mvps/r1_a/validator.py::_validate_payload`): new
   `_matches_type()` — bool is explicitly excluded from int and float
   (`isinstance(True, int)` is True in Python); float accepts int
   (JSON numbers) but never bool; nested `{"type": "object",
   "properties": {...}}` / `{"type": "array", "items": ...}` specs are
   checked recursively. Flat string specs unchanged.
4. **Streaming** (`StreamingHandler`): single `_pending` replaced by a
   dict keyed by correlation key — `item.id`, then `item.call_id` (the
   form the recorded #41708 fixtures carry), then `output_index`, then
   `item_id`; anonymous calls get distinct keys. Keyless deltas go to the
   most recently added pending call (unambiguous when one call is
   pending; deltas for a non-pending call are dropped, never mis-
   attributed). Duplicate done → ignored and recorded; done for a
   never-added call → orphan, recorded, no completed emitted.
   `validate_stream` now passes iff the completed set equals the done
   set for known calls with no orphans (single-call old behaviour
   preserved: 1 done → 1 completed, 0 done → 0).
5. **Event contract**: key priority verified against the recorded #41708
   events in `mvps/r1_a/data/fixtures.json` (call_id "call_1", no
   output_index) and the adversarial tests (item.id "a"/"b"). No protocol
   field was guessed beyond those two observed forms plus the standard
   Responses API `output_index`/`item_id` fields, which are covered by
   tests.
