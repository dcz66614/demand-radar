## 1. R1-A — real paths added

### (a) Recorded-event replay (real input, no simulated transport)
The #41708 / #41710 event sequences in `mvps/r1_a/data/fixtures.json`
are fed through the REAL `StreamingHandler` (`tests/test_real_paths.py`):
correct handler emits exactly 1 completed chunk with the recorded
arguments `{"q": "paris"}`; the buggy handler (emit_on_done=False) emits
0 despite the done event arriving; the #41710 no-done sequence emits 0.
The scenario runner's streaming path and the direct replay agree
(3 scenarios each).

### (b) Real tokenizer (tiktoken 0.14.0)
New module `mvps/r1_a/real_tokenizer.py`. tiktoken was pip-installable
and its encoding tables fetched from OpenAI's public blob store on
first `get_encoding` (cached afterwards; tests run offline after that).
Measured on the #340 fixture texts (2026-11-06):

| text | cl100k (GPT-4) | o200k (gpt-4o) | substitution detectable? |
|---|---|---|---|
| Chinese | 51 | 34 (+50%) | yes |
| Japanese | 54 | 43 (+25.6%) | yes |
| English | 19 | 19 | no — identical counts |
| code | 13 | 13 | no — identical counts |

`validate_token_count_real` detects a REAL default substitution
(gpt-4o count reported as the cl100k count) on Chinese/Japanese, and
passes a correct real count. For any model with no tiktoken encoding
(e.g. `litellm/qwen3-coder-30b` from #340) `count_tokens_real` returns
`None` and `validate_token_count_real` raises `ValueError` — it never
silently approximates. The #340 Qwen substitution therefore stays
**NOT_REAL_WORLD_VALIDATED** (approximation only, `validator.py`).

### (c) Factual correctness by content, never by flag
New `check_factual_content` (`validator.py`): the fixture supplies the
ground truth (`expected_answer`, `expected_keywords`,
`forbidden_claims`); the response passes only if every expected keyword
is present and no forbidden claim is. The `factual=False` payload flag
was REMOVED from `SimulatedTransport` and from `_validate_payload` —
the transport no longer grades its own homework. The HN #50382039
fixture step now carries `expected_answer: "The capital of France is
Paris."`, keywords `["paris"]`, forbidden `["berlin"]`; the false
response is convicted by missing "paris". A new positive-control
scenario `true-response-openrouter` passes. Fixtures: 15 scenarios,
22 checks (was 14 / 21).

### (c, continued) `count_tokens_for_model`
Still an approximation, same counter for every non-OpenAI model name —
now documented as such in its docstring, which points at
`real_tokenizer.py` for real validation. No claim remains that it
detects real tokeniser substitution on real models.

  offset PRDs eliminated by re-scoring. Labels are in each README
  ("Positioning" section), each app's warning banner, and this report.

## 7. NOT_TESTED / remaining honest gaps

- No REAL API call was made for R1-A (no live OpenAI/OpenRouter call,
  no paid calls, no network calls at test time). Streaming replay uses
  recorded event sequences, not a live stream.
- The #340 Qwen substitution has no real-tokenizer proof (no Qwen
  tokenizer was installed; installing `transformers` + a Qwen
  tokenizer was not attempted — out of scope for this stage, and the
  claim is labelled accordingly rather than faked).
- Real RSA agreement is loose (delta 0.518 vs the PRD's 0.05): the two
  algorithms differ, and the 1.0 bound is a documented
  cross-implementation bound, not a PRD tolerance.
- The local DFA implementation (1.4348) and real `fractal_dfa`
  (1.3329) differ on the same signal; only the real function's
  invariance is asserted.
- The fixture's intended EMG band (10, 500) Hz differs from upstream's
  envelope default (10, 400) Hz; the failure class, not the exact band,
  is what the real path validates.
- tiktoken's encoding tables need one network fetch on first use;
  in a fresh offline environment the 7 real-tokenizer tests skip.
