## 1. 改了什么

### 1.1 trapz 测试修复（唯一生产无关的测试缺陷）
文件：`mvps/r1_b/tests/test_signalcheck.py::test_signal_power_does_not_use_removed_trapz`

- **删除**了 `assert not hasattr(np, "trapz")`。理由（brief 明确授权，记录在此）：
  某版本 NumPy 的属性列表是外部库的实现状态，不是本项目的软件要求；
  NumPy 2.3.5 中 `np.trapz` 仍存在（本阶段实测 `hasattr(np, "trapz") is True`），
  而生产代码早已正确使用 `np.trapezoid`。旧断言在正确代码上失败，
  所以断言本身是缺陷，不是被测代码。
- **保留并加强**了真正的要求（同一测试内）：
  - (a) 生产代码调用 `numpy.trapezoid`：源码含 `"np.trapezoid("`；
  - (b) 生产代码绝不调用旧 API：源码不含 `"np.trapz("`（注释/docstring/字符串里
    出现 `np.trapz` 不算调用，允许；实测出现在 `signalcheck.py` 第 22、24、
    432、436、455 行，均为注释或文档字符串，唯一调用在第 441 行
    `np.trapezoid(squared, dx=dt)`）；
  - (c) 数值正确：A=2 正弦信号 `signal_power(...) == 2.0 ± 0.01`
    （与已有 `test_signal_power_matches_analytic_value` 同值，双重覆盖）。
- 没有降低任何阈值，没有为让错误代码通过而改预期：生产代码 `signalcheck.py`
  **未动**；数值容差 0.01 与原测试一致。

### 1.2 AppTest 确定性等待条件（R2-02 新发现的第二种抖动）
文件：`mvps/r1_a/tests/test_app_r1a.py`、`mvps/r1_b/tests/test_app_r1b.py`

- 观测到的失败（2026-11-06，NumPy 2.3.5 环境，6 个 AppTest 只跑时）：
  `mvps/r1_a/tests/test_app_r1a.py::test_app_runs_and_shows_results_after_click`
  在 `at.button[0].click().run()` 抛错，根因是 Streamlit AppTest 内部
  `require_widgets_deltas` 在**默认 3 秒**超时内未收到 ScriptRunner 完成事件
  （`local_script_runner.py:198`，`timeout = 3`）。这与 R06/R07 记录的
  “dataframe 未渲染”抖动是**不同机制**。
- 修复：所有 `run()` 调用改为显式 `run(timeout=30)`（初次运行、点击、settle、
  过滤器共 8 处/文件对）。这是确定的等待条件与超时断言，不是重跑：
  30 秒是固定上界，脚本若真挂起仍会失败；没有任何重试循环。
  注释中记录了观测、根因与上界，见两文件 `_click_and_settle`。
- 附带：R07 的 bounded settle（点击后最多 2 次额外 `run()`）保留未动。

### 1.3 工作台 AppTest 驱动脚本（新增证据脚本，非测试）
文件：`reports/rework2/apptest_workbench_r2_02.py`（日志
`apptest_workbench_r2_02_main.log`、`apptest_workbench_r2_02_numpy23.log`）

工作台 `app/streamlit_app.py` 原先没有任何 AppTest 文件（只有两个 MVP 有），
本阶段补了一个驱动脚本：默认 200 条 VERIFIED、勾选显示 REJECTED、领域/来源/

均记录在 §4（`at.write` 在 Streamlit 1.67 不存在；关键词断言只查标题，
而 SQL 是标题 OR 摘要匹配）。

工作台脚本自身修过的两个 bug（均在本阶段内、修后重跑通过）：
1. 首次运行 `AttributeError: 'AppTest' object has no attribute 'write'`——
   Streamlit 1.67 的 AppTest 没有 `at.write`，`st.write` 输出以 markdown 元素暴露；
   改为在 `at.markdown` 中找“共 …”计数行。
2. 关键词断言失败：脚本只检查标题 markdown 含 "token"，但 SQL 是
   `title LIKE OR excerpt LIKE`；DB 核对确认 6 行中有 1 行（"Support for o4-mini"）
   仅摘要含 token。改为标题与随后摘要 markdown 二者任一含关键词即通过。
   这是脚本断言写错，不是应用 bug。
